## Jarvis 5.1 — Gaming AI Mode
- Voice-gated Gaming AI mode: «جارویس، خودت بازی کن»
- Stop command: «جارویس، بس کن»
- Mode is OFF by default and remains OFF until explicitly enabled.
- The release is designed for game analysis/assistance and does not bypass anti-cheat protections.


## Jarvis 5.2 — Live Game Screen Analysis
- «جارویس، خودت بازی کن» explicitly enables Gaming AI and requests Android screen-capture permission.
- While enabled, Jarvis periodically analyzes the latest game frame and reports a short Persian tactical summary by voice.
- «جارویس، بس کن» stops Gaming AI and the screen-capture service.
- Android requires explicit MediaProjection approval for screen capture.
- No touch/key injection, anti-cheat bypass, or guaranteed-win behavior is included.

## Jarvis 5.4 (this fix) — Real cause of "never turns into an APK"
The project was missing its **Gradle wrapper** (`gradlew`, `gradlew.bat`,
`gradle/wrapper/gradle-wrapper.jar`, `gradle-wrapper.properties`). This is
required for any Gradle/Android project to build. `codemagic.yaml` tried to
work around the missing wrapper by downloading a `gradle-wrapper.jar` from
an unrelated path inside the `gradle/gradle` source repository — that file
is not a valid, guaranteed-correct redistribution of the wrapper, so the
download step was unreliable and the whole Codemagic build failed before
compilation ever started. That is why no APK was ever produced.

Fixed in this version:
- Added a proper `gradle/wrapper/gradle-wrapper.properties` pinned to
  Gradle 8.4 (matches AGP 8.2.0 / Kotlin 1.9.22 / JDK 17 already used by
  the project), plus standard `gradlew` / `gradlew.bat` launcher scripts.
- Rewrote `codemagic.yaml`: it no longer downloads a wrapper jar from an
  unrelated GitHub path. Instead it uses Codemagic's own pre-installed
  Gradle to generate a genuine, correct wrapper for this project, then
  builds normally with `./gradlew assembleDebug`.
- `.github/workflows/build.yml` now also triggers on `master` (not just
  `main`) and on pull requests, in case the default branch name was the
  reason it never ran automatically.
- Fixed `GeminiClient.kt`: it was calling the non-existent model
  `gemini-3.7-flash`, which always returned HTTP 404 from Google's API —
  meaning the AI answers / Gaming AI screen analysis never worked even
  after a successful build. Changed to the valid `gemini-2.5-flash`.
- No feature, screen, permission, or setting was removed — everything
  from the settings/control-center panel is unchanged.

### If you build locally / in Android Studio
`gradle-wrapper.jar` itself is a small binary file and could not be
generated by hand here. The very first CI run (Codemagic or GitHub
Actions) regenerates it automatically before building, so CI works out
of the box. To build locally before that:
```
gradle wrapper --gradle-version 8.4
./gradlew assembleDebug
```
(any locally installed Gradle, or Android Studio's bundled Gradle, can
run the `wrapper` command once — after that `./gradlew` works on its own).
